# DamageLife Update Checker

## Цель

Проверять наличие новой версии DamageLife, не создавая постоянной нагрузки во время игры.

## Политика производительности

DamageLife **не** выполняет проверку каждые 10–30 минут.

Проверка должна удовлетворять всем условиям:

1. не чаще одного раза в 24 часа;
2. только асинхронный backend;
3. не во время боя;
4. не во время БГ/арены;
5. без `OnUpdate`-polling;
6. без синхронного HTTP, который может блокировать UI;
7. ответ — только метаданные Release, без загрузки ZIP в память аддона;
8. обновление файлов выполняется вручную через GitHub Release.

## Почему обычный Lua не может сделать HTTPS

Стандартный WoW 3.3.5a addon sandbox не предоставляет произвольный сетевой HTTPS API. Поэтому `UpdateChecker.lua` не пытается открывать sockets и не подключает LuaSocket/lua-requests напрямую.

## Backend contract

Если инфраструктура клиента/сервера предоставляет разрешённый асинхронный HTTP backend, он регистрируется через:

`DamageLifeUpdateChecker.SetHTTPBackend(function(url, callback) ... end, "backend-name", true)`

Callback получает:

`body, statusCode, headers, error`

Backend должен быть асинхронным. Синхронные реализации намеренно отклоняются.

## Поток данных

`GitHub Releases API → async backend → UpdateChecker → SavedVariables → Settings UI`

В самом аддоне нет постоянного сетевого процесса.

## Память

Update Checker не хранит большие ответы и не сохраняет ZIP. После разбора ответа остаются только короткие строки версии/названия/ссылок и timestamp последней проверки.

Во время боевого цикла модуль не выполняет периодических операций.

## Важное ограничение

Без host/relay backend стандартный WoW 3.3.5a не сможет выполнить настоящий HTTP-запрос к GitHub. В таком случае модуль просто остаётся неактивным и не создаёт дополнительной фоновой нагрузки.
